# Нумерация элементов Revit

Плагин назначает марки стенам, дверям и окнам и записывает номера помещений. Перед записью окно показывает текущие и предлагаемые значения, а также причины, по которым некоторые строки будут пропущены.

## Сборка и установка

Нужны Windows, SDK .NET 8 или новее и средства сборки для .NET Framework 4.8. Ссылочные сборки Revit восстанавливаются из NuGet. Они нужны при компиляции, при запуске API предоставляет установленный Revit.

```powershell
dotnet build src/Numbering.Revit/Numbering.Revit.csproj -c Release -p:RevitVersion=2023
dotnet build src/Numbering.Revit/Numbering.Revit.csproj -c Release -p:RevitVersion=2024
dotnet build src/Numbering.Revit/Numbering.Revit.csproj -c Release -p:RevitVersion=2025
```

Для Revit 2023 и 2024 используется `net48`, для Revit 2025 — `net8.0-windows`. При необходимости можно собрать со своими библиотеками, передав, например, `-p:RevitApiDir="C:\Program Files\Autodesk\Revit 2024"`. Указывайте каталог API той же версии, которую передали в `RevitVersion`. Параметр по умолчанию — `2024`.

1. Закройте нужную версию Revit.
2. Выполните из корня репозитория `& .\deploy\Install-Addin.ps1 -RevitVersion 2024`, подставив свой год. Скрипт устанавливает две DLL и манифест в `%APPDATA%\Autodesk\Revit\Addins\<год>\` для текущего пользователя.
3. Запустите Revit, откройте проект и на вкладке «Надстройки» / «Add-Ins» нажмите «Нумерация элементов».
4. Для ручной установки скопируйте `Numbering.Revit.dll`, `Numbering.Core.dll` и `deploy/ElementNumbering.addin`. В манифесте укажите абсолютный путь к `Numbering.Revit.dll`, сам манифест положите в папку `Addins\<год>\`. Для удаления уберите манифест и папку `ElementNumbering` из папки этой версии.

## Использование

Выберите категорию, охват и шаблон. Поиск работает по части ID, имени, уровня или текущего значения без учёта регистра. В режиме «Видимые в таблице» охват состоит из всех строк после поиска, включая строки ниже области прокрутки. В режиме «Выбранные в модели» охват берётся из выделения Revit. Поиск в этом режиме меняет только отображение, а строка состояния показывает, сколько выбранных к обработке скрыто поиском.

Пример шаблона — `Д-{Уровень}-{N:000}`. Можно задать префикс в отдельном поле и вставить его через `{Префикс}`. Подстановка `{N:000}` обязательна и встречается один раз. От одного до девяти нулей задают минимальную ширину числа, например `007`, `125` или `1001` при трёх нулях. Подстановка уровня необязательна. Если одинаковые числа на разных уровнях при этом дают одинаковые номера, плагин покажет конфликт.

Раскройте «Конфликты предпросмотра» над таблицей, чтобы увидеть предложенные номера, ID и причины. Список включает выбранные элементы, скрытые поиском. Нажмите «Применить» после проверки предпросмотра. Сводку записи можно развернуть под таблицей. После операции таблица перечитывает фактические значения. При внешнем изменении модели прежний расчёт сбрасывается.

## Как устроен код

| Проект | Ответственность |
|---|---|
| `Numbering.Core` | Поиск, разбор шаблона, обход рядов по уровням, расчёт номеров и разрешение конфликтов. Получает обычные C#-данные. |
| `Numbering.Revit` | Команда и окно WPF, ViewModel и сеанс окна, Revit API, настройки и журнал. |
| `Numbering.Core.Tests` | Модульные тесты логики, запускаемые отдельно от Revit. |

`NumberingSession` обрабатывает смену категории и запросы на применение через `ExternalEvent`. `Idling` отвечает за чтение и подготовку порциями, а также за финальную запись в контексте Revit. Окно работает в отдельном диспетчере WPF и получает готовый снимок. При переходе на другой документ снимок сбрасывается. Перед записью плагин сверяет активный документ, снимок категории и выделение в режиме «Выбранные в модели».

Для добавления типовой категории достаточно записи в `CategoryDefinition.All`, например для несущих колонн `OST_StructuralColumns` с `ALL_MODEL_MARK` и своим префиксом. `ModelReader` уже умеет читать обычную точку и ось. Если у новой категории другой способ определения уровня или положения, дополните соответствующий метод в `ModelReader`. Шаблон, таблица, выбор охвата и запись используют общие правила.

### Порядок

Счётчик стартует с 1 для каждого ID уровня. Для стены берётся середина оси, для двери, окна и помещения — точка размещения. Если у стены не найден `LevelId`, используется нижняя привязка. Элементы без уровня или точки остаются в таблице с причиной пропуска.

Используются координаты модели. На каждом уровне ряд начинается с максимального оставшегося Y. Элементы в пределах 300 мм от начала ряда сортируются по X, затем по ElementId при равном X. Новая точка начинает следующий ряд. Сортировка по ID проще, но не отвечает пространственному порядку. Округление Y до фиксированной сетки может разнести соседние элементы по разным рядам на границе такой сетки. Отсчёт от начала ряда также исключает постепенный дрейф ряда при длинной цепочке соседних точек.

Границы рядов строятся по всей категории до применения поиска и выделения. Поэтому элемент вне охвата может задавать начало ряда. Номера получают только элементы охвата, в порядке уже построенных рядов. Так смена охвата сохраняет относительный порядок общих элементов.

### Конфликты и совместная работа

Занятость номера проверяется по всей категории активного проекта. Для сравнения обрезаются пробелы по краям и игнорируется регистр. Строки с занятым номером или одинаковой целью пропускаются. Существующий номер без изменения сохраняется. Переназначение внутри охвата допустимо, когда все нужные номера освобождаются в той же записи. Если одна запись отклонена, её старый номер продолжает занимать место, и зависимые строки проверяются заново.

Выбран пропуск отдельных строк с сохранением номеров, показанных в предпросмотре. Автоматический выбор следующего свободного номера дал бы другие значения. Остановка всей операции из-за одного конфликта помешала бы записать остальные строки.

Перед записью плагин проверяет, доступен ли параметр для изменения. В совместной модели доступ к элементу определяется по результату записи и фиксации транзакции. При отказе с известными ID плагин откатывает попытку, исключает эти строки и пересчитывает конфликты перед повтором. Если ошибку нельзя привязать к изменяемым элементам, плагин откатывает операцию целиком и показывает сообщение Revit в сводке. Только успешное завершение добавляет шаг Undo. Предупреждения собираются в сводку и журнал.

### Настройки

Файл `%LocalAppData%\ElementNumbering\settings.json` содержит категорию, режим охвата, префиксы и шаблоны по категориям. Параметры общие для установленных версий под одним профилем Windows. Такой выбор позволяет сохранить личные предпочтения без записи в общую модель. Поиск, выделение и значения элементов в настройках не сохраняются. Чтобы сбросить настройки, закройте окно и удалите этот JSON. При повреждённом файле используются настройки по умолчанию. Журнал находится в `%LocalAppData%\ElementNumbering\numbering.log`.

## Проверка

```powershell
dotnet test tests/Numbering.Core.Tests/Numbering.Core.Tests.csproj -c Release
dotnet test tests/Numbering.Core.Tests/Numbering.Core.Tests.csproj -c Release --filter FullyQualifiedName~LargeCategoryTests --logger "console;verbosity=detailed"
```

В чистой копии Git прошли 30 тестов. Проверены в том числе поиск, неверные шаблоны, граница допуска ряда, элементы без уровня и координат, оба охвата, обмен номерами, конфликты со строками вне охвата и пересчёт конфликтов после отказа записи. Собраны Release для Revit 2023, 2024 и 2025 без ошибок и предупреждений. Для каждой сборки установочный скрипт проверен в отдельной папке. Синтаксис скрипта также проверен под Windows PowerShell 5.1.

Отдельный тест WPF подтвердил, что конфликт скрытого элемента виден при выключенной кнопке «Применить», а ошибка в шаблоне очищает список. В Revit 2025.1 на двух синтетических стенах проверили отказ одной записи на этапе `Commit`. Первая попытка откатилась целиком. При повторе свободная стена получила номер, у пропущенной сохранилась прежняя марка, а её ID и причина появились в сводке. Отказ в этом тесте создавал стенд. ### Замеры

Синтетический набор Core состоит из 10 200 строк стен на трёх уровнях. Три прогона Release на AMD Ryzen 9 9900X. Таблица показывает медиану и максимальное время из трёх прогонов.

| Операция Core | Медиана | Максимум |
|---|---:|---:|
| Пространственная сортировка | 2,87 мс | 9,54 мс |
| Поиск по части имени | 0,35 мс | 0,73 мс |
| Охват, номера и конфликты | 21,84 мс | 36,63 мс |

Базовый замер сделан в **Revit 2025.1 (25.1.0.44)** на синтетической модели с **10 200 стенами на двух уровнях**. В каждом из трёх прогонов стенд проверил фактические марки всех стен после записи. Один вызов Undo вернул все 10 200 прежних значений, и предпросмотр обновился.

|---|---:|

В финальном прогоне окно плагина работало с собственной очередью ввода Windows. Главный интерфейс Revit всё ещё заметно задерживался при записи. Требование об отзывчивости при записи 10 000+ элементов подтверждено частично.

Для повторения замера используйте отдельную модель с 10 000+ экземпляров одной категории. Между прогонами меняйте префикс или отменяйте запись, чтобы запись выполнялась для всех элементов. Журнал содержит время чтения, время предпросмотра для 10 000+ строк и отдельные времена `Set` и `Commit`. Отзывчивость измерялась интервалом между срабатываниями таймеров двух окон с периодом 20 мс. При ручной проверке дополнительно проверьте ввод и прокрутку.

### Проверка перед сдачей

- Открыть окно дважды, переключить между двумя проектами, закрыть активный проект, затем последний.
- Проверить все четыре категории, в том числе помещение без положения, поиск, два охвата и ошибочный шаблон.
- Занять номер элементом вне охвата. В режиме «Выбранные в модели» скрыть конфликтующую строку поиском и найти её ID и причину в «Конфликтах предпросмотра».
- Открыть две локальные копии тестовой совместной модели под разными пользователями. В первой занять одну стену. Во второй применить новый префикс к этой и к свободной стене. Проверить, что у занятой стены сохранилась марка и в сводке есть её ID и причина, а свободная стена получила номер. Одним Undo вернуть прежнюю марку свободной стены.
- Проверить, что следующее Undo возвращает все прежние значения, а таблица их перечитывает. Перезапустить Revit и проверить восстановление настроек.
- Повторить замеры внутри Revit 2023 и 2024. Наличие сборок и время Core не подтверждают отзывчивость интерфейса во время записи в этих версиях.

## Известные ограничения

- Нумеруются экземпляры активного проекта. Элементы связанных файлов остаются вне охвата.
- Порядок привязан к осям модели. Поворот вида не меняет направление рядов для расчёта.
- Одна финальная транзакция сохраняет один шаг Undo. Запись и фиксация выполняются в основном потоке Revit. Главное окно Revit может ждать их окончания, а окно плагина обрабатывает свои события отдельно. Время транзакции зависит от модели и других надстроек.
- Для Revit 2023 и 2024 подтверждена компиляция. Запуск внутри этих версий и сценарий с двумя пользователями совместной модели пока не подтверждены.
